## 5.37.4 — What's New / Fixes

- **Short-sneaking experiment (server):** The `short_sneaking` experiment is enabled server-side and advertised to clients via `StartGamePacket`, enabling short-sneak behaviour (1.5-block) on supported clients.

- **Crawling / short-sneak (server-side):**
  - Crawling intents in `PlayerAuthInputPacket` (START_CRAWLING / STOP_CRAWLING) are intercepted server-side and mapped to swimming flags (START_SWIMMING / STOP_SWIMMING) so the client remains in the lowered pose.
  - A per-session `isCrawling` state is maintained; while a player is lowered the server will reassert the START_SWIMMING flag.
  - The server preserves the sneak state for players kept lowered so they can still move while lowered and not get stuck when under slabs / 1.5-block spaces even if the client releases the sneak key.

- **Standing detection:** The server uses AxisAlignedBB collision checks to determine whether a player can stand up. If enough vertical clearance exists the crawling state is cleared; otherwise the server forces the client to remain lowered.

- **Network / client synchronization:** When there are mismatches while toggling crawling/sneak/swim states, the server resynchronizes the player's metadata so the client and server remain consistent.

- **Changed files (summary):**
  - `src/network/mcpe/handler/InGamePacketHandler.php` — Updated `PlayerAuthInputPacket` handling: crawling intent mapping, `isCrawling` protection, AABB-based standing detection, sneak flag enforcement.
  - `src/network/mcpe/handler/PreSpawnPacketHandler.php` — `short_sneaking` experiment enabled at `StartGamePacket`.

Note: A prior crash report related to the `Chicken` class (passive/namespace mismatch) was fixed by the contributor; no additional chicken-specific changes are included in this release.

User note: These changes focus on keeping the client in a lowered pose server-side; if you still see cases where the client stands up, provide logs or reproduction steps and additional synchronization measures can be added.
